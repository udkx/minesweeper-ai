# Сапёр + нейросеть

Свой движок игры, точный логический решатель как эталон, свёрточная сеть,
которая учится видеть мины, и веб-визуализация, где всё это можно посмотреть.

Готовы этапы 1–3. Этап 4 (Rust, микросекунды, CoreML) — впереди.

## Результаты

Уровень «средний» (16×16, 40 мин), 300–400 партий на каждого:

| Агент | Винрейт | Открыто клеток | Время партии |
|---|---|---|---|
| случайные клики | 0.0 % | 36.6 % | 0.5 мс |
| **нейросеть, сама** | **71.6 %** | 85.8 % | 43 мс |
| **нейросеть + тривиальные правила** | **74.3 %** | 87.0 % | 51 мс |
| точный решатель | 87.5 % | 94.4 % | 229 мс |

Точный решатель на трёх уровнях: **96.7 %** новичок, **87.5 %** средний,
**41.3 %** эксперт. Это близко к теоретическому потолку — оставшиеся проигрыши
не ошибки, а позиции, где информации объективно не хватает.

Важная оговорка про 71.6 %: это **очень маленькая** сеть (65 тысяч параметров,
3 блока по 32 канала), обученная на 120 тысячах позиций за 4 эпохи **на CPU
в два ядра**. Она нужна была только чтобы проверить, что весь конвейер работает.
Полная конфигурация (`--channels 64 --blocks 6`, 400+ тысяч позиций, 12+ эпох)
на M1 Pro считается минуты и должна дать заметно больше.

## Главный результат — не винрейт, а вот это

Сеть обучалась на жёстких метках: для каждой клетки ноль или один, мина или нет.
Никаких вероятностей в разметке не было ни разу. Вот что она выдаёт:

```
      предсказано → на самом деле мин   (клеток)
         0.8%    →    0.8%   (  313930)
        15.6%    →   15.7%   ( 1470381)
        24.4%    →   25.3%   (   42473)
        34.9%    →   37.5%   (   30981)
        44.9%    →   46.5%   (   27049)
        54.7%    →   52.4%   (   20483)
        64.7%    →   59.6%   (   13684)
        74.9%    →   70.7%   (   10563)
        85.2%    →   83.6%   (   10207)
        99.8%    →   99.8%   (  497155)
```

Сеть сказала «здесь мина с вероятностью 15.6 %» — мины оказались в 15.7 %
случаев. Она выучила вероятности, которых ей никогда не показывали.

Почему так получается. Одна и та же картинка поля встречается в разных партиях
то с миной в клетке, то без. Кросс-энтропия — это функция, которая
минимизируется ровно тогда, когда модель выдаёт **частоту** события, а не
пытается угадать конкретный исход. Модель, которая на такой картинке говорит
«0 или 1», в среднем ошибается сильнее, чем модель, которая говорит «0.156».
Так что жёсткие метки плюс правильный лосс дают на выходе вероятность.

Отсюда же и потолок: перечисление конфигураций в `solver.py` даёт **точную**
вероятность, а сеть может только приблизиться к ней. Смысл сети не в том, чтобы
обогнать решатель по качеству, а в том, чтобы выдавать похожий ответ за один
проход вместо экспоненциального перебора — 43 мс на партию против 229 мс.

Кривизна в середине таблицы (35 % → 37.5 %) — это как раз недоученность
маленькой модели. Хорошая проверка после полного прогона: середина должна
подтянуться.

## Файлы

Этап 1 — игра и эталон:

| Файл | Что внутри |
|---|---|
| `minesweeper.py` | движок: расстановка мин, каскад нулей, условие победы |
| `solver.py` | точный решатель: правила вывода + перечисление конфигураций |
| `play.py` | прогон партий, замер винрейта, запись партии в JSON |
| `minesweeper.html` | классический сапёр в браузере + смотрелка партий ИИ |
| `build_html.py` | вшивает записи партий в html |

Этап 2 — данные:

| Файл | Что внутри |
|---|---|
| `batch_engine.py` | тысячи досок одновременно в массивах (B, H, W) |
| `fast_policy.py` | тривиальные правила на сдвигах + эвристика угадывания |
| `dataset.py` | сбор датасета, проверка целостности, статистика |

Этап 3 — сеть:

| Файл | Что внутри |
|---|---|
| `model.py` | полносвёрточная сеть, кодирование поля, выбор устройства |
| `train.py` | обучение, метрики, калибровка |
| `nn_agent.py` | агент на сети, замер винрейта, режимы pure и hybrid |

Тесты: `test_engine.py` (9), `test_solver.py` (5), `test_batch.py` (6),
`test_model.py` (5). Все проходят.

## Запуск

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install numpy torch

# тесты (test_solver идёт ~2 минуты, он сверяется с полным перебором)
python test_engine.py && python test_batch.py && python test_model.py
python test_solver.py

# данные: обучение и валидация — из РАЗНЫХ партий, отсюда разные seed
python dataset.py make --positions 400000 --seed 0   --out data_train.npz
python dataset.py make --positions 40000  --seed 999 --out data_val.npz

# обучение (на M1 Pro сам подхватится MPS)
python train.py --epochs 12 --channels 64 --blocks 6

# сколько выигрывает
python nn_agent.py --model minenet.pt --difficulty intermediate --games 500
python play.py bench --all --games 200          # эталон для сравнения

# посмотреть партию сети в браузере
python play.py record --agent net --model minenet.pt --difficulty intermediate \
    --want-win --min-guesses 2 --out replay_net.json
python build_html.py решатель=replay.json сеть=replay_net.json
```

`minesweeper.html` открывается двойным кликом, сервер не нужен. Во вкладке
«Смотреть ИИ» переключатель `решатель / сеть` — стоит сравнить карты. У
решателя она резкая: точные нули, точные единицы, ровные дроби вроде 33 %.
У сети размытая, и точных нулей в ней не бывает вообще — сигмоида не умеет в
ровный ноль. Это и есть разница между «доказал» и «оценил», видимая глазом.

## Как устроен решатель

Сапёр сводится к системе уравнений: каждая открытая цифра говорит «среди этих
закрытых соседей ровно N мин». Три уровня, от дешёвого к дорогому:

1. **Тривиальные правила.** N = 0 → все соседи безопасны. N = числу закрытых
   соседей → все они мины. Крутим до упора: каждая найденная мина уменьшает
   счётчики у соседей и открывает новые тривиальные случаи.

2. **Правило подмножеств.** Если множество A целиком внутри B, то в разнице
   B \ A ровно (N_B − N_A) мин. Этим человек ловит узор 1‑2‑1.

3. **Перечисление.** Когда правила встали — перебираем все расстановки мин,
   совместимые с видимыми цифрами, и считаем, в какой доле из них клетка
   оказалась миной.

Пункт 3 звучит как 2^480 вариантов, но спасают две вещи. Информация есть только
на границе открытого — остальное поле одна большая лотерея, которая считается
биномиальными коэффициентами. И граница почти всегда разваливается на
независимые куски: левый угол не влияет на правый, поэтому 2^40 превращается
в 2^12 + 2^14 + …

`test_probabilities_match_brute_force` сверяет результат с тупым перебором на
поле 5×5 — 1028 позиций совпали до 1e-9.

## Как устроена сеть

Никакого пулинга и никаких полносвязных слоёв. Обычный классификатор сжимает
картинку до вектора («это кошка»), а нам нужен ответ для каждой клетки: карта
поля на входе, карта вероятностей того же размера на выходе.

Свёртки подходят к сапёру не случайно: правила игры локальны и одинаковы во всех
частях поля. Свёртка — это буквально «одно правило, применённое ко всем
клеткам», то есть в модель заранее заложено ровно то допущение, которое в задаче
верно. Полносвязной сети пришлось бы выучивать правило заново для каждой из 256
клеток, и данных ушло бы в сотни раз больше.

Побочный эффект: сеть не привязана к размеру поля. Обучил на 16×16 — запускаешь
на 16×30 без единого изменения (`test_model_shapes_and_size_independence`).

Вход — 12 каналов: 10 на состояние клетки (закрыта + цифры 0..8), канал единиц
(по нему сеть отличает край поля от пустоты, которую дописывает padding), и
канал общей плотности мин — то же, на что человек смотрит в счётчике.

One-hot для цифр, а не одно число, потому что цифры сапёра — категории, а не
величины. «3» не в три раза больше «1», и один канал навязал бы модели ложный
линейный порядок.

Дальность обзора собирается послойно: 5×5 на входе плюс блоки по два слоя 3×3.
Шесть блоков дают ±14 клеток — это важно, потому что в сапёре бывают длинные
цепочки вывода вдоль границы открытого.

## Три грабли, на которые легко наступить

**Датасет из случайных позиций.** Соблазн: взять случайную доску, случайно
приоткрыть половину клеток, готово. Так получаются картинки, которых в настоящей
игре не бывает — например, одинокая открытая пятёрка посреди закрытого поля
(в реальной игре к ней сначала пришёл бы каскад). Сеть отлично выучит
несуществующую задачу. Поэтому позиции берутся из настоящих партий, сыгранных
`fast_policy`.

**Скоррелированные примеры.** Позиции внутри одной партии отличаются на одну
открытую клетку. Если ссыпать все подряд, «400 тысяч примеров» окажутся четырьмя
тысячами партий, и модель будет переобучаться, показывая при этом отличную
валидацию — потому что валидация набрана так же. Поэтому из партии берётся
случайная часть позиций (`--keep-prob`), а обучение и валидация идут от разных
партий (разный `--seed`). `dataset.py stats` печатает долю уникальных полей,
за ней стоит следить.

**Лосс по всем клеткам.** У открытых клеток ответ известен заранее — мины там
нет по определению. Включать их в лосс значит бесплатно улучшать цифру, ничего
не улучшая по существу. Считаем только по закрытым.

## Метрики, потому что «лосс падает» ничего не значит

Базовый уровень: предсказывать всем закрытым клеткам одну и ту же среднюю
плотность мин (на «среднем» уровне это 32.8 %). Такая модель даёт loss 0.6330.
Сеть даёт 0.3081. Если бы разрыва не было, значит она не выучила ничего, кроме
статистики.

`safe-pick` — доля позиций, где клетка с минимальной предсказанной вероятностью
действительно не мина. У модели выше 99.91 %. Это и есть игровое качество: сеть
ровно так и выбирает ход. По этой метрике имеет смысл сравнивать модели, а не по
лоссу.

Калибровка — таблица выше.

## Что дальше, этап 4

Порт горячих частей на Rust с битбордами и погоня за микросекундами. Здесь
чистая логика обгонит нейросеть: один проход свёрточной сети — сотни
микросекунд, из которых большая часть даже не счёт, а накладные расходы на
запуск ядер на GPU. Скоростной рекорд и рекорд по винрейту — два разных
соревнования.

Отдельная приятная опция: обученную сеть можно экспортировать в CoreML и
запустить на Neural Engine — том самом, с которого всё началось. На обучении он
недоступен ни PyTorch, ни TensorFlow (MPS — это Metal, то есть GPU), а вот на
инференсе работает.

Ещё направления, если захочется:

- **Дообучение на своих партиях.** Сейчас датасет собирает `fast_policy`.
  Собрать его партиями самой сети — она будет учиться на тех позициях, в которые
  сама себя загоняет. Это классический DAgger, и обычно даёт заметный прирост.
- **Обучение сразу на трёх уровнях сложности.** Сеть полносвёрточная, размер
  поля ей не мешает, а разная плотность мин — полезная добавка к обобщению.
- **Дистилляция решателя.** Учить не на жёстких метках, а на точных
  вероятностях из `solver.py`. Сигнал богаче, сходиться должно быстрее — но
  данных получится собрать намного меньше, потому что решатель медленный.
  Интересно, что победит.
