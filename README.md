# Сапёр + ИИ: этап 1 из 4

Движок игры, точный логический решатель и веб-визуализация. Нейросети пока нет —
и это специально: сначала нужен противник, которого сеть будет догонять,
и цифры, с которыми можно сравнивать.

## Что уже работает

| Файл | Что внутри |
|---|---|
| `minesweeper.py` | движок игры на numpy: расстановка мин, каскад нулей, условие победы |
| `solver.py` | точный решатель: правила вывода + перечисление конфигураций мин |
| `play.py` | прогон партий, замер винрейта, запись партии в JSON |
| `minesweeper.html` | классический сапёр в браузере + смотрелка записанных партий ИИ |
| `build_html.py` | вшивает записанную партию в html (браузер не читает локальный json) |
| `test_engine.py` | 9 тестов движка |
| `test_solver.py` | 5 тестов решателя, включая сверку вероятностей с полным перебором |

## Запуск

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install numpy

python test_engine.py            # 9 тестов
python test_solver.py            # 5 тестов, ~2 минуты
python play.py bench --all --games 200
```

Открыть `minesweeper.html` двойным кликом — играется само, сервер не нужен.

Записать свою партию и посмотреть её:

```bash
python play.py record --difficulty expert --want-win --min-guesses 3 --out replay.json
python build_html.py replay.json
```

## Цифры эталона

Прогон на этой машине (одно ядро, чистый Python + numpy):

| Уровень | Винрейт | Открыто клеток | Время партии |
|---|---|---|---|
| Новичок 9×9, 10 мин | **96.7 %** | 99.6 % | 16 мс |
| Средний 16×16, 40 мин | **87.5 %** | 94.4 % | 229 мс |
| Эксперт 16×30, 99 мин | **41.3 %** | 78.3 % | 790 мс |

Это близко к теоретическому пределу. Оставшиеся 58 % проигрышей на «эксперте» —
не ошибки решателя, а позиции, где информации объективно не хватает: две клетки,
в одной из них мина, и никакой алгоритм не скажет в какой. Проверить это можно
глазами — в смотрелке такие ходы подписаны как «угадывает, риск N %».

## Как устроен решатель

Сапёр целиком сводится к системе уравнений. Каждая открытая цифра говорит:
«среди этих закрытых соседей ровно N мин». Дальше три уровня:

1. **Тривиальные правила.** Если N = 0 — все соседи безопасны. Если N равно числу
   закрытых соседей — все они мины. Крутим до упора: каждая найденная мина
   уменьшает счётчики у соседей и открывает новые тривиальные случаи.

2. **Правило подмножеств.** Если множество клеток A целиком внутри B, то в разнице
   B \ A ровно (N_B − N_A) мин. Это то, чем человек ловит узор 1‑2‑1.

3. **Перечисление.** Когда правила встали — честно перебираем все расстановки мин,
   совместимые с видимыми цифрами, и смотрим, в какой доле из них клетка оказалась
   миной. Это и есть настоящая вероятность.

Пункт 3 звучит как «2^480 вариантов», но спасают две вещи. Во-первых, информация
есть только на границе открытого — остальное поле это одна большая лотерея,
которая считается биномиальными коэффициентами. Во-вторых, граница почти всегда
разваливается на независимые куски: левый угол не влияет на правый, поэтому
2^40 превращается в 2^12 + 2^14 + …

Тест `test_probabilities_match_brute_force` сверяет результат с тупым перебором
на поле 5×5 — 1028 позиций совпали до 1e-9. Это важно: дальше эти вероятности
станут ориентиром для нейросети, и если бы они врали, ошибку было бы почти
невозможно найти.

## Почему движок и в Python, и в JS

Запись партии содержит только расстановку мин и список ходов — визуализатор в
браузере переигрывает партию своим движком. Это не только уменьшает файл в
десять раз, но и работает как проверка: если правила в JS и Python хоть немного
расходятся, воспроизведение ломается заметно (партия, которая была победой,
перестаёт ей быть). Сейчас они совпадают ход в ход.

## Что дальше

**Этап 2 — данные.** Векторизованный движок, который гоняет тысячи досок
одновременно, и сбор датасета из миллионов позиций. Ключевая тонкость: нельзя
брать случайную доску и случайно её приоткрывать — такие позиции в реальной игре
не встречаются, и сеть выучит не ту задачу. Позиции надо набирать из настоящих
партий.

**Этап 3 — сеть.** Свёрточная сеть без пулинга: на входе поле в виде 11 каналов
(по одному на каждую возможную цифру плюс «закрыто»), на выходе карта вероятностей
того же размера. Учим на правде о минах обычной кросс-энтропией.

Тут есть красивый момент, который стоит понять заранее. Метки будут нулями и
единицами: «мина» / «не мина». Но одна и та же картинка поля встречается в
разных партиях то с миной, то без. Кросс-энтропия минимизируется, когда сеть
выдаёт **частоту** — то есть ровно ту вероятность, которую решатель считает
перебором. Сеть, обученная на жёстких 0 и 1, сходится к вероятностям, которых в
метках никогда не было. Это же и объясняет, почему сеть не может превзойти
решателя: она в лучшем случае приближает его ответ.

**Этап 4 — рекорды.** Порт горячих частей на Rust с битбордами и погоня за
микросекундами. Здесь чистая логика обгонит нейросеть: один проход свёрточной
сети — это сотни микросекунд, из которых большая часть даже не счёт, а накладные
расходы на запуск ядер на GPU.

Отдельная приятная опция на этапе 4: обученную сеть можно экспортировать в CoreML
и запустить на Neural Engine — том самом, про который был исходный вопрос. На
обучении он недоступен ни PyTorch, ни TensorFlow, а вот на инференсе работает.
